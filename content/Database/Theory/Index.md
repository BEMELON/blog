# Index
인덱스(Index)는 데이터베이스에서 데이터를 빠르게 찾기 위한 구조로, 책의 마지막에 있는 찾아보기(색인)처럼 데이터의 위치를 쉽게 찾아주는 역할을 합니다. 인덱스는 테이블 내 특정 열(column)이나 열 조합에 대해 만들어지며, 이를 통해 데이터를 검색하거나 정렬할 때의 속도를 크게 향상시킵니다.

## Index가 효율적인 이유

1. **빠른 데이터 접근**: 인덱스는 데이터가 저장된 실제 위치를 기억하고 있어 원하는 데이터를 바로 찾아갈 수 있습니다. 예를 들어, 순차적으로 데이터를 읽는 것보다 인덱스를 통해 데이터의 위치를 알면, 필요한 데이터만 바로 접근할 수 있어 검색 속도가 빨라집니다.

2. **검색 및 조회 성능 향상**: 대규모 데이터셋에서 원하는 데이터를 찾기 위해 모든 행(row)을 탐색하는 것은 매우 비효율적입니다. 인덱스를 사용하면 검색 범위를 좁혀서 특정 데이터를 빠르게 찾을 수 있습니다. 예를 들어, B-Tree나 Hash 인덱스 구조는 데이터의 위치를 효과적으로 지정하여 검색 성능을 최적화합니다.

3. **정렬 작업 최적화**: 인덱스는 정렬된 순서로 데이터를 저장하거나 참조하기 때문에 ORDER BY 구문과 같은 정렬 작업이 더 빠르게 수행됩니다. 인덱스가 적용된 열은 이미 정렬된 상태이므로 별도의 추가 작업 없이 결과를 반환할 수 있습니다.

4. **고유성 보장 (Unique Index)**: 인덱스는 데이터의 고유성을 보장할 수 있도록 도와줍니다. UNIQUE 제약 조건과 결합하여 특정 열에 중복 값이 들어가지 않도록 할 수 있습니다.

5. **조인 성능 향상**: 여러 테이블을 조인할 때, 인덱스를 사용하면 조인 키에 대한 데이터를 빠르게 찾을 수 있어 조인의 성능이 크게 향상됩니다. 이는 복잡한 쿼리를 수행할 때 매우 유용합니다.

  

## **인덱스의 한계**
인덱스가 효율적이지만, 모든 경우에 적합한 것은 아닙니다. 인덱스는 추가적인 저장 공간을 필요로 하며, 데이터 삽입, 수정, 삭제 작업에서 오버헤드가 발생할 수 있습니다. 따라서 인덱스를 사용할 때는 주로 조회 빈도가 높은 열에 적용하는 것이 효율적입니다.
